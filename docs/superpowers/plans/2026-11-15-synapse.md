# Synapse implementation plan

**Goal:** Implement docs/synapse.md and a nearly viewport-sized animated Home experience without changing playback APIs.
**Architecture:** Local catalog and per-user online learning in FastAPI/SQLite; additive queue metadata and React hooks; existing audio service unchanged.
**Spec:** docs/synapse.md. Existing design and defaults explicitly authorized by the implementation request.
**Rollback baseline:** 7217532 (includes the pre-existing documentation), branch feat/synapse. Revert feature commits to restore code. New tables can remain unused after rollback; existing favorites and library tables are untouched.

- [x] Backend: additive schema, normalization seeds, resumable-safe periodic catalog snapshot, bounded candidate pools, diversity, moods, online feedback, authenticated API. Verify temporary SQLite tests for filters, events, cooldowns, ownership, reset, failed sync and 100k performance.
- [x] Frontend logic: persisted filters, API, telemetry with actual listening time and retry, guarded auto-continue, settings/reset. Verify helpers, queue guards, TypeScript build and existing seek regression tests.
- [x] Home: large Synapse panel before existing content, multi-select familiarity and toggleable moods, mix rows with reasons, refreshing/play states and playback animation. Verify browser interactions, responsive layout and reduced motion.
- [x] Integration: review implementation against spec, run backend tests/frontend checks, document verified limits, commit all task changes.

Review focus: seek must not count as listening; stale requests after queue/account changes must be discarded; favorites-only must stay exact; failed sync must preserve catalog; repeat must never trigger continuation.
